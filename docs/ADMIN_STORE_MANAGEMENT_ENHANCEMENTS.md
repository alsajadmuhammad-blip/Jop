# تحسينات إدارة المتاجر للمشرف (Admin Store Management Enhancements)

## نظرة عامة
تم تحسين صفحة إضافة المتاجر (`/admin/add-store`) بشكل شامل لتوفير تجربة مستخدم احترافية وعالية الجودة مع محاذاة كاملة مع مخطط قاعدة البيانات.

## التحسينات الرئيسية

### 1. واجهة منظمة بتبويبات (Tabbed Interface)
تم تقسيم النموذج إلى 5 تبويبات منطقية لتنظيم أفضل:

#### التبويب الأول: المعلومات الأساسية
- **اسم المتجر** - مع عداد الأحرف (حد أقصى 100)
- **الموقع الجغرافي** - المحافظة والمدينة
- **وصف المتجر** - حقل نصي كامل لوصف الخدمات والمنتجات (حد أقصى 500 حرف)
- **إحداثيات GPS** - خط العرض (Latitude) وخط الطول (Longitude)
- **نوع المتجر** - فعلي (محل) أو إلكتروني (أونلاين)

#### التبويب الثاني: صاحب الحساب
- **اسم صاحب المتجر** - مع التحقق من الطول الأدنى (3 أحرف)
- **البريد الإلكتروني** - مع التحقق من الصيغة
- **كلمة المرور** - حد أدنى 6 أحرف
- **تأكيد كلمة المرور** - التحقق من التطابق
- **رقم الواتساب** - مع التحقق من الصيغة

#### التبويب الثالث: الإعدادات
- **نوع السوق/النشاط** - مع خيار إضافة نوع جديد
- **الباقة الاشتراكية** - اختيار من الباقات المتاحة
- **خدمة التوصيل** - تفعيل/تعطيل خدمة التوصيل
- **ساعات العمل** - تحديد ساعات العمل لكل يوم من الأسبوع:
  - 7 أيام (السبت إلى الجمعة)
  - وقت الفتح والإغلاق لكل يوم
  - خيار تحديد اليوم كمغلق (مثل الجمعة)

#### التبويب الرابع: الصور
- **شعار المتجر** - رفع صورة للشعار (JPG, PNG, GIF, WebP - حد أقصى 5MB)
- **صورة الغلاف** - رفع صورة غلاف جذابة (JPG, PNG, GIF, WebP - حد أقصى 10MB)
- **معاينة الصور** - عرض الصور قبل الإرسال

#### التبويب الخامس: المراجعة
- **معاينة شاملة** - عرض جميع البيانات المدخلة
- **تأكيد البيانات** - للتأكد من صحة المعلومات قبل الإرسال

### 2. التحقق من صحة البيانات المحسّن

تم إضافة دالة `validateForm()` شاملة تتحقق من:

```javascript
✓ اسم المتجر (مطلوب، حد أدنى 3 أحرف)
✓ اسم صاحب المتجر (مطلوب، حد أدنى 3 أحرف)
✓ البريد الإلكتروني (صيغة صحيحة)
✓ كلمة المرور (حد أدنى 6 أحرف)
✓ تأكيد كلمة المرور (تطابق)
✓ رقم الواتساب (صيغة صحيحة)
✓ الإحداثيات (صيغة GPS صحيحة إذا تم إدخالها)
```

### 3. رفع الصور (Image Upload)

تم تطبيق نظام احترافي لرفع الصور:
- رفع آمن عبر Supabase Storage
- دعم تنسيقات متعددة (JPG, PNG, GIF, WebP)
- حدود حجم معقولة (5MB للشعار، 10MB للغلاف)
- معاينة فورية قبل الإرسال
- رسائل خطأ واضحة عند الفشل

**الملفات المستخدمة:**
- `uploadFile()` من `supabase-storage.ts`
- Bucket: `store-logos` و `store-covers`

### 4. معالجة ساعات العمل (Business Hours)

نظام متقدم لتحديد ساعات العمل:
- واجهة تفاعلية لكل يوم من أيام الأسبوع
- اختيار وقت الفتح والإغلاق بصيغة 24 ساعة
- تحديد الأيام المغلقة (مثل الجمعة)
- حفظ البيانات في صيغة JSON في قاعدة البيانات

**الصيغة:**
```json
{
  "saturday": { "open": "09:00", "close": "22:00", "closed": false },
  "sunday": { "open": "09:00", "close": "22:00", "closed": false },
  ...
  "friday": { "open": "09:00", "close": "22:00", "closed": true }
}
```

### 5. تجربة المستخدم المحسّنة

#### مؤشرات بصرية
- أيقونات واضحة لكل حقل
- رسائل حالة (معلومات، تحذيرات، أخطاء)
- تلوين الزر حسب الحالة
- تحميل تقدمي مع رسائل ("جاري رفع الصور..."، إلخ)

#### سهولة الاستخدام
- تصميم متجاوب (Responsive) يعمل على جميع الأجهزة
- عداد الأحرف للحقول المحدودة
- رسائل توضيحية أسفل الحقول
- التنقل السلس بين التبويبات

### 6. تعديل البيانات المرسلة

تم توسيع البيانات المرسلة إلى Edge Function:

```typescript
await createStoreOwner({
  ownerEmail: string
  ownerName: string
  ownerPassword: string
  storeName: string
  storeDescription: string          // جديد
  whatsappNumber: string
  marketType: string
  packageName: string
  storeType: string
  location: string
  latitude: number | null
  longitude: number | null
  hasDelivery: boolean              // جديد
  businessHours: object             // جديد
  logoUrl: string | null            // جديد
  coverUrl: string | null           // جديد
})
```

## التوافق مع قاعدة البيانات

### جدول `stores`

```sql
-- الحقول الجديدة المدعومة:
- description TEXT
- has_delivery BOOLEAN
- business_hours JSONB
- logo_url TEXT

```

### الحقول المعتمدة:

| الحقل | النوع | الملاحظة |
|-------|-------|---------|
| name | VARCHAR | إسم المتجر |
| description | TEXT | وصف المتجر |
| owner_name | - | عبر جدول auth.users |
| owner_email | VARCHAR | بريد صاحب الحساب |
| password | - | عبر نظام المصادقة |
| whatsapp_number | VARCHAR | رقم التواصل |
| market_type | VARCHAR | نوع السوق |
| store_type | VARCHAR | فعلي/إلكتروني |
| location | TEXT | الموقع الجغرافي |
| latitude | NUMERIC | إحداثيات GPS |
| longitude | NUMERIC | إحداثيات GPS |
| has_delivery | BOOLEAN | خدمة التوصيل |
| business_hours | JSONB | ساعات العمل |
| logo_url | TEXT | رابط الشعار |
| cover_image_url | TEXT | رابط صورة الغلاف |
| package_id | UUID | الباقة المختارة |
| is_active | BOOLEAN | حالة التفعيل |

## الاستخدام

### الوصول إلى الصفحة
```
/admin/add-store
```

### التدفق:
1. المشرف يضغط على "إضافة متجر جديد" من صفحة الإدارة
2. يتم توجيهه إلى صفحة النموذج المحسّن
3. يملأ البيانات عبر التبويبات الخمسة
4. يرفع الصور (اختياري)
5. يراجع البيانات في التبويب الأخير
6. يضغط "إنشاء المتجر الآن"
7. يتم إرسال البيانات إلى Edge Function
8. يتم حفظ المتجر في قاعدة البيانات
9. يتم تحويل المشرف إلى لوحة المتاجر

## التحسينات المستقبلية المقترحة

1. **استيراد البيانات من ملف** - إضافة خيار لاستيراد متاجر من ملف CSV/Excel
2. **نسخ من متجر موجود** - السماح بنسخ إعدادات متجر موجود
3. **معاينة حية للمتجر** - عرض معاينة حية لكيفية ظهور المتجر للعملاء
4. **تحميل الشعار من URL** - إضافة خيار لإدخال رابط شعار بدلاً من الرفع
5. **المزيد من الخيارات** - إضافة حقول إضافية مثل العملة المستخدمة، الفئات المتاحة، إلخ
